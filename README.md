# 整理券システム（WEB版・無料）

- `docs/index.html` お客さん用（QRの行き先）
- `docs/admin.html` スタッフ用（ログイン必須）
- `docs/board.html` 掲示モニター用
- `firestore.rules` データベースのルール（変更したらFirebaseコンソールに貼り直す）

## 構成
画面はGitHub Pagesで公開し、データはFirebase(Firestore, 無料のSpark)に保存します。

## セットアップ
1. Firebase: Firestore作成、Authentication(メール/パスワード)でスタッフユーザー追加、ウェブアプリ登録（済）
2. Firestoreの「ルール」タブに `firestore.rules` の中身を貼って公開
3. Authentication → 設定 → 承認済みドメイン に `cain218.github.io` を追加
4. GitHubの Settings → Pages → Branch: `main` / フォルダ: `/docs` → Save
5. 公開URL `https://cain218.github.io/seiriken/` をQRコード化して掲示

## 画面のURL
- お客さん: `https://cain218.github.io/seiriken/`（テスト用: 末尾に `?test=1`。管理メニューの「テスト券を削除」で消せます）
- スタッフ: `.../admin.html`（スマホ・タブレット向け。開いたままにしておくと全体の状況を更新します）
- 掲示モニター: `.../board.html`

## 運用
- 番号は日付(日本時間)ごとに1から自動リセット。
- 流れ: 順番待ち → 呼び出し → 入室済み（お客さんが待機室で半券をもぎる、またはスタッフが「入室済みにする」）で完了。
- あと2組（自分の前に1組）で「まもなく順番です」と表示。呼び出されると画面が変わる（音・通知は出さない）。
- 状態は 順番待ち／呼び出し中／入室済み／欠席／キャンセル の5つ。来ない組は、行をタップして「後ろへ回す」（順番待ちの3組目と4組目の間に戻る）。順番待ちの行は、右端の「≡」を長押ししてドラッグすると並べ替えられる。「欠席」「発券停止」は管理画面から。
- 管理画面の「履歴」で、今日の整理券がどうなったか（入室・キャンセル・欠席、待った時間、時刻）を一覧で見られます。

## 人数・列からの切り替え
- 人数は1〜8人。2人1組で1枚なので、3人以上は整理券が複数枚になる（3人＝2名＋1名の2枚）。お客さん画面にはタブで枚数分が並ぶ。
- スタッフ画面の「設定」→「列から整理券に切り替える」で、今並んでいる組数・人数を入力すると、番号のない「列」の組が順番待ちの先頭に入る。入室したら「入室済みにする」。
- スタッフ画面の「人数を記録」で、整理券を使わない入室（空いている時間など）の人数を入室済みとして記録できる。

## 通信の警告とエラーコード
- お客さん画面の上の帯: 通信が5分切れたら赤（WT-N1。切れている間は1分ごとに自動でつなぎ直す）、順番の更新が5分止まったら黄色（WT-S3。お客さんには「スタッフ」とは書かず「順番の更新が止まっている」と出す。中身はスタッフ画面の生存確認）。つながると緑で「つながりました」。
- スタッフ画面: 赤い帯に「○分前から」を表示。呼び出し中の行に「届いた 時刻」（お客さんの画面に表示された）／1分たっても「未確認」。紙の券には出ない。
- スタッフ画面は1分ごとに `summary/日付-hb` へ生存確認を書く。お客さん画面は、呼び出し中か前に3組以内のときだけ、5分ごとにそれを1回だけ読む。
- 失敗したときは「原因」と「エラーコード（操作-原因）」を表示。操作: IS発券 TR もぎり CA キャンセル WT状態取得 OP操作 PP紙発券 QU列追加 WK人数記録 CF設定 DL削除 UN元に戻す LG ログイン。
  原因: N1オフライン N2応答なし P1許可されていない（ルール未反映） A1ログイン切れ Q1上限 C1他端末が先に操作 G1見つからない S1発券停止中 S3スタッフ更新停止 B1入力・ログイン情報 X0不明（コードの後ろに生のエラー名）。
- 「呼び出しが届いた」印のため `firestore.rules` を更新したので、コンソールに貼り直すこと（貼り忘れても動くが、印は出ず「未確認」のままになる）。

## お知らせ・連絡（v49）
- お客さん画面を開くと、1日1回「ご確認ください」（不具合はメッセージ機能か受付へ／ネットが不安定だと進まない／一周2名まで／待ち時間は目安／通知は来ないので開いたままにする）が出る。
- 設定の「待ち時間の目安」: 自動（実績）／手入力（1組○分）／出さない。counters の `waitMode` `waitMin`（古い `showWait` も読む）。
- 受付とのダイレクトメッセージ（v51）: `ticket.dm` に `{f:'s'（受付）|'c'（お客さん）, t, at, code?}` を並べる（1通100文字・全部で40通まで）。スタッフは行をタップ→「お客さんとのメッセージ」で送る（紙・列・人数記録の券は対象外）。お客さんは券の画面の上のカード（「返信する」で履歴を開く。「確認しました」ボタンはなく、既読だけ）。メッセージの候補（ひな形）は出さないか、下の「受付にメッセージを送る」から送る。履歴は吹き出しで、たくさんあるとスクロールする。
- 既読: お客さんの画面に出ると `dmSeenAt`（スタッフ画面に「既読」）、スタッフが開くと `dmReadAt`（お客さんに「既読」）。お客さんから未読のメッセージは、スタッフ画面の上に赤い枠で出る（「開いて返信」「既読にする」）。直前のエラーコードも添えて送れる。
- 読み取り: 1通あたり、読み取り約2〜3回（スタッフ画面とお客さんの券の購読に1回ずつ）と書き込み1回（既読で+1回ずつ）。購読は増えない。
- `firestore.rules` を更新したので、貼り直すこと（`dm` と `dmSeenAt` の許可を追加）。
- 全員にお知らせ（v50）: 設定の一番上。`counters` の `notice`/`noticeAt` に書き、集計経由で全員の画面の上に出る（書き込み1回。読み取りは開いている人の分）。お客さんは「閉じる」で消せる（同じお知らせは再表示しない）。
